# BoardMate Arcade v11.1 — 2026-09-04 작업 반영

> v10 인수인계 문서를 기반으로 이어서 수정한 버전입니다. 아래 v11.1 변경사항이 기존 내용보다 우선합니다.

## v11.1 변경사항
- 게임 취소 RPC `boardmate_set_cancel_vote` / `boardmate_get_cancel_status`를 최종 재정의하고 `notify pgrst, 'reload schema'`를 추가했습니다.
- 방 생성 RPC `create_boardmate_room_v8`도 최종 재생성합니다. 빠른 복구용 **`SUPABASE_RPC_FIX_v11_1.sql`**은 방 생성 + 취소 RPC를 한 번에 복구하고 schema cache를 reload합니다. 앱은 v8 RPC가 schema cache에 없을 때 v7 RPC로 한 번 자동 fallback합니다.
- `online-calico.html`을 사용자가 새로 제공한 Board-Mate Arena 대응 Calico HTML로 교체하고, BoardMate Supabase 방 상태/좌석/자동저장/재접속/ELO 어댑터를 연결했습니다.
- `online-cascadia.html`을 사용자가 새로 제공한 Cascadia PVP HTML로 교체하고, PeerJS 대신 BoardMate 방에서는 Supabase 공유 상태를 사용하도록 연결했습니다. 새 버전의 A/가족/중급 점수 선택과 회전 반투명 미리보기를 유지합니다.
- 펜토리니의 v11 전체 합법 위치 34% 반투명 미리보기는 사용자 요청으로 제거했습니다. **펜토리니는 v10 동작으로 되돌렸으며**, 회전/뒤집기는 우측 선택 타일 미리보기만 갱신하고 보드 전체 후보를 표시하지 않습니다.
- 사용자 표시 이름 `포켓노바`를 `포크노바`로 변경했습니다. 내부 호환 키/파일 경로 `pocketnova`는 유지합니다.
- 새 Calico 상태는 현재 차례 키가 `active`이므로 `boardmate_turn_seat`가 Calico에서 `active`를 우선 읽도록 보강했습니다.

## 0. 프로젝트 한 줄 요약

**BoardMate Arcade**는 약 100명 규모의 보드게임 모임원들이 GitHub Pages에서 접속해:

- 간단한 **미니게임**을 매일/상시 플레이하고 순위표를 보고,
- **1인플** 게임을 AI/솔로 또는 외부 공개 웹 구현으로 플레이하고,
- **다인플**에서는 로그인 후 방을 만들어 여러 명이 온라인 턴제로 플레이하고,
- 게임별 비공개 ELO를 기반으로 닉네임 앞에 랭킹/메달을 표시하는

모임용 보드게임 웹사이트입니다.

# 1. 가장 중요한 현재 결정사항 — 다음 작업에서 절대 되돌리지 말 것

1. **리코셰 로봇은 완전히 포기/삭제했습니다.**
   - 다시 추가하지 않습니다.
   - 관련 UI/라우트/게임 코드는 현재 메인 앱에서 제거되어 있습니다.

2. 메인 첫 화면의 섹션 이름은 **`오늘의 게임`이 아니라 `미니게임`**입니다.
   - 현재 미니게임은 **펜토리니 + Yahtzee 2개**입니다.
   - 2개 카드가 화면 너비를 반씩 사용하도록 `daily-two` 디자인이 적용되어 있습니다.

3. 다인플의 **`실시간 / 턴제` 선택은 제거**했습니다.
   - 현재 모든 온라인 게임은 **턴 기반 + 행동 시 자동 저장 + 재접속** 방식 하나로 통일했습니다.
   - 전원이 접속해 빠르게 진행해도 되고, 자기 차례에 나중에 다시 들어와도 같은 구조입니다.

4. 방을 만들 때 **인원 수는 사용자가 정하지 않습니다.**
   - 게임별 최소/최대 인원만 코드에서 제한합니다.
   - 방장이 원하는 시점에 `게임 시작`을 누릅니다.

5. 게임별 **ELO 숫자는 비공개**입니다.
   - ELO 1~5위: `#1` ~ `#5`
   - 그 외 골드: `🥇`
   - 실버: `🥈`
   - 브론즈: `🥉`
   - **`브론즈`, `실버`, `골드` 같은 큰 글자는 인게임에 표시하지 않습니다. 메달만 표시합니다.**

6. 캘리코 / 캐스캐디아 외부 1인플 구현은 **BoardMate 자체 다인플을 검증·개선하기 위한 참고 구현**으로 봅니다.
   - 캘리코: `https://myautoma.github.io/games/calico/index.html`
   - 캐스캐디아: `https://cascadiagame.github.io/`
   - 현재 `solo-calico.html`, `solo-cascadia.html`은 이 외부 게임을 여는 wrapper로 남아 있습니다.
   - 하지만 사용자의 핵심 의도는 wrapper 자체가 아니라, **외부 구현의 공개 소스를 찾아 현재 `online-calico.html`, `online-cascadia.html`의 보드 좌표/룰/점수 로직을 대조하는 것**입니다.
   - 다음 세션에서는 GitHub Pages에 연결된 실제 저장소가 공개되어 있는지와 라이선스를 먼저 확인합니다. 공개 저장소라면 구현을 참고하되, 라이선스 범위를 지킵니다.

7. **포크노바 1인플은 지금 추가하지 않습니다.**
   - 추후 만들 때는 AI 대전이 아니라 **아크노바 공식 1인플 전용 규칙을 포크노바 엔진에 적용**하는 방식으로 만들 예정입니다.
   - `solo-pocketnova.html` 파일이 폴더에 남아 있어도 현재 메인 1인플 목록에는 연결하지 않습니다.

8. **룰북 PDF는 ZIP에 넣지 않습니다.**
   - 용량 절약 목적입니다.
   - 규칙 작업이 다시 필요하면 사용자가 해당 룰북을 재업로드하는 방식으로 진행합니다.

9. 계정은 Supabase Auth 이메일 가입을 쓰지 않습니다.
   - 예전에 `email rate limit exceeded` 문제가 발생해서 폐기했습니다.
   - 현재는 **닉네임 + 비밀번호/PIN** 자체 계정 시스템입니다.
   - 비밀번호 최소 길이는 **4자**입니다.

10. 방 제목을 입력하지 않으면 자동으로 생성합니다.
    - 예: `민수의 캘리코 한 판`

# 3. 기술 구조

## 프론트엔드

- 순수 HTML / CSS / JavaScript
- npm 없음
- 빌드 없음
- GitHub Pages에서 정적 파일로 실행
- `index.html` → `app.js`
- 온라인 게임은 각자 `online-*.html`
- 온라인 공통 통신은 `multi-common.js`

## 백엔드

- Supabase PostgreSQL
- Supabase JS CDN 사용
- `config.js`에 공개용 Project URL + anon/publishable key만 넣음
- **service_role key는 절대 프론트엔드에 넣지 않음**

`config.js` 예시:

```js
window.BOARDMATE_CONFIG = {
  supabaseUrl: "https://xxxx.supabase.co",
  supabaseAnonKey: "공개용_anon_publishable_key"
};
```

# 4. 설치 / 업데이트 방법

## GitHub Pages

1. ZIP을 풉니다.
2. 폴더 안 파일을 GitHub 저장소 root에 전부 덮어씁니다.
3. 기존 `config.js`에 이미 Supabase URL/key가 있다면 그 값은 유지합니다.
4. GitHub → Settings → Pages → Deploy from branch → `main` / `/ (root)`

## Supabase

**v10 기준 `supabase.sql` 전체를 SQL Editor에서 다시 실행해야 합니다.**

경로:

`Supabase 프로젝트 → SQL Editor → New query → supabase.sql 전체 붙여넣기 → Run`

SQL 파일은 지금까지 기능을 누적한 형태라 일부 함수가 뒤에서 `create or replace`로 다시 정의됩니다. 다음 작업에서 함부로 중간 정의를 삭제하지 말고 **최종 정의가 무엇인지 확인 후 정리**하는 것이 안전합니다.

# 5. 회원 / 로그인 / 관리자

## 회원가입 / 로그인

- 이메일 없음
- 닉네임 + 비밀번호/PIN
- 비밀번호 최소 4자
- 자체 `boardmate_profiles`, `boardmate_sessions` 기반
- 비밀번호 원문은 저장하지 않고 해시만 저장

로그인/회원가입은 별도 로그인 화면에 있고, 비밀번호 변경 등 계정 기능은 **마이페이지**에 있습니다.

## 관리자 지정

처음 한 번 Supabase **SQL Editor**에서 실행:

```sql
select public.admin_set_boardmate_admin('내닉네임', true);
```

이후 로그인 → **마이페이지 → 회원 관리** 사용.

## 현재 관리자 기능

- 회원 목록
- 기간 정지
- 정지 해제
- 영구 퇴출
- 영구 퇴출 닉네임 재가입 차단
- 관리자 본인의 계정은 자기 자신 정지/퇴출 불가

## 운영자가 회원 비밀번호 강제 초기화

Supabase SQL Editor에서:

```sql
select public.admin_reset_boardmate_password('회원닉네임', '1234');
```

기존 비밀번호 원문을 보는 기능은 없습니다.

# 9. 온라인 자동 저장 / 재접속

온라인 게임 상태는 `boardmate_room_state`에 JSON 형태로 저장합니다.

현재 동작:

- 행동할 때마다 자동 저장
- 브라우저 닫아도 방 멤버 자리를 바로 삭제하지 않음
- 다인플 첫 화면에 **진행 중인 게임** 표시
- `이어하기`로 같은 자리 복귀
- 현재 차례가 나면 `내 차례` 표시
- 방 목록에 현재 누구 차례인지 표시

## 접속 상태

`boardmate_room_members.last_seen_at` heartbeat 사용.

약 **20초** 동안 heartbeat가 없으면:

- `● 접속` → `○ 끊김`

으로 표시됩니다.

이는 탈퇴가 아니라 접속 상태 표시일 뿐입니다.

# 10. 게임 취소 투표 — v10 핵심

모든 온라인 게임에 `게임 취소` 버튼을 추가했습니다.

규칙:

- 진행 중인 게임에서 참가자 누구나 취소 동의 가능
- 동의 철회 가능
- `현재 동의 수 / 현재 방 멤버 수` 표시
- **현재 방 참가자 전원이 동의해야 취소 확정**
- 접속 끊긴 사람도 아직 방 멤버면 전원 수에 포함
- 취소되면 room status=`cancelled`
- 취소 게임은 승/패/ELO에 반영하지 않음

관련 DB:

- `boardmate_room_cancel_votes`
- `boardmate_get_cancel_status(...)`
- `boardmate_set_cancel_vote(...)`

관련 프론트 공통 코드:

- `multi-common.js`

### v11 취소 RPC 오류 복구

`Could not find the function ... in the schema cache`가 보이면 Supabase에 해당 RPC가 아직 생성/노출되지 않은 상태입니다. v11.1의 `SUPABASE_RPC_FIX_v11_1.sql` 전체를 SQL Editor에서 실행하면 **방 생성 + 취소 RPC 재생성 + PostgREST schema reload**까지 한 번에 수행합니다. 전체 `supabase.sql`을 다시 실행해도 됩니다.

### 주의 / 향후 논의 가능점

현재는 **완전한 만장일치**라 장기 미접속자가 있으면 취소가 막힐 수 있습니다. 이것은 현재 의도한 규칙입니다. 향후 사용자가 원하면 `접속자 전원`, `방장 강제 종료`, `24시간 무응답 제외` 같은 정책을 별도로 논의할 수 있습니다.

# 11. 다인플 티어 / ELO 규칙

게임마다 ELO는 별도이며 **숫자는 사용자에게 숨깁니다.**

표시 우선순위:

1. ELO 전체 1~5위 → `#1`~`#5`
2. 6위 이하이면서 2승 이상 + 승률 50% 이상 → `🥇`
3. 1승 이상 → `🥈`
4. 그 외 → `🥉`

사용자가 원한 룰:

- 4인 게임 기준 1등 = 1승
- 나머지 2/3/4등 = 각각 1/3패
- 일반화하면 N인 게임에서 1위 외 플레이어는 `1/(N-1)`패 취급

인게임에서는 메달/랭킹만 작게 보이며 **브론즈/실버/골드 글씨는 표시하지 않는 방향**입니다.

다음 대화에서 이 게임의 규칙을 깊게 수정해야 한다면 사용자에게 해당 자료를 다시 업로드 요청하면 됩니다.

- 캘리코 한국어 게임 설명서 PDF
- 캐스캐디아 한국어 규칙서 PDF
- 노터치 크라켄 디럭스 한국어 게임 설명서 PDF
- 더 게임: 이룰 수 없는 미션 한국어 설명서 PDF
- 마스크맨 AI HTML
- 어콰이어 AI HTML
- 더 게임 HTML
- 노터치 크라켄 HTML
- Pocket Nova v2 ZIP

현재 ZIP 안에는 실제 실행에 필요한 게임 소스는 대부분 포함되어 있지만, **PDF 룰북은 의도적으로 제외**했습니다.

# 17. 다음 세션에서 우선 확인해야 할 것

다음 작업자가 ZIP을 받았을 때 아래 순서로 확인하면 좋습니다.

## 1순위 — Supabase 다기기 E2E 테스트

실제 프로젝트 키를 넣은 후 계정 2~4개로:

1. 회원가입/로그인
2. 방 생성
3. 다른 계정 참가
4. 방장 시작
5. 행동 자동 저장
6. 브라우저 닫기
7. 20초 후 `○ 끊김` 확인
8. 다시 접속 → `이어하기`
9. `내 차례` 표시 확인
10. 게임 취소 투표 → 전원 동의 → cancelled 확인
11. 정상 게임 종료 → 결과/ELO 1회만 반영 확인

## 2순위 — 캐스캐디아 재접속 버그 재검증

특히:

- 한 플레이어가 선택지에서 타일+동물을 가져간 상태
- 아직 자기 생태계 배치가 끝나지 않은 상태
- 다른 플레이어가 화면 새로고침/재접속

했을 때 더 이상 `habitats` null 오류가 없어야 합니다.

## 3순위 — 캘리코 실물 보드 시각 검증

- 5×5 엇갈린 육각 내부 배치
- 디자인 타일 3칸 위치
- 플레이 가능 22칸
- 가장자리 인쇄 헝겊 22칸
- 실제 플레이어 보드별 가장자리 색/무늬 배치 정확성
- 고양이 1점/2점/3점 그룹
- 모양 3/4/5칸 조건

현재 구조는 개선되어 있지만 **실물 4개 플레이어 보드와 완전 동일한 고정 가장자리 데이터인지 추가 검증 필요**합니다.

## 4순위 — 포크노바

온라인은 아직 베타.
다음에 작업한다면 먼저:

- 원본 엔진 TODO 확인
- 실제 지도/수치 정확성 검증
- 온라인 좌석별 비밀 정보가 다른 브라우저에서 노출되지 않는지 확인

그 후 1인플을 한다면 **아크노바 공식 솔로 룰 기반**으로 진행.

# 18. 현재 알려진 한계 / 주의사항

1. **실제 Supabase 프로젝트에서 완전한 다계정 E2E는 개발 환경상 대신 실행하지 못했습니다.**
   - 문법/코드 수준 검증과 로컬 로직 검증은 했지만 실제 사용자 Supabase에서 최종 확인 필요.

2. 온라인 게임 상태는 브라우저에서 접근 가능한 JSON을 기반으로 합니다.
   - 모임원끼리 쓰는 신뢰 기반 구현입니다.
   - 개발자도구로 상대의 비밀 상태를 악의적으로 읽는 것까지 강하게 막는 구조는 아닙니다.
   - 완전한 비밀정보 보안이 필요하면 향후 Supabase Edge Function / 서버 검증 구조 필요.

3. 방장 강퇴는 현재 **게임 시작 전 대기실만** 지원합니다.
   - 게임 도중 강퇴는 좌석·손패·비밀 역할·턴 인덱스 문제 때문에 일부러 막았습니다.

4. 게임 취소는 접속 끊긴 사람도 포함한 **전원 동의**입니다.

5. 외부 캘리코/캐스캐디아 1인플은 BoardMate가 직접 제어하지 않지만, 다음 작업에서 **공개 저장소 소스를 찾아 자체 온라인 다인플의 규칙/보드 구현을 검증하는 참고 자료**로 사용합니다.

6. 포크노바 온라인은 베타이며 원본 엔진 자체에도 TODO가 많습니다.

7. 캐스캐디아 온라인은 **A 카드 + 초심자·가족/중급 변형**까지 자동 계산하며 B/C/D 카드는 아직 미구현입니다.

# 19. 다음 작업자가 코드 수정 전에 읽어야 할 체크리스트

- [ ] 리코셰를 다시 만들지 않는다.
- [ ] `오늘의 게임`이라는 이름을 다시 쓰지 않는다. `미니게임`이다.
- [ ] 턴제/실시간 선택 UI를 다시 만들지 않는다. 현재는 턴 기반 하나다.
- [ ] 방 인원수를 생성 시 선택하게 만들지 않는다.
- [ ] 티어 텍스트를 크게 표시하지 않는다. 메달/`#1~#5`만 사용한다.
- [ ] 룰북 PDF를 배포 ZIP에 넣지 않는다.
- [ ] 캘리코/캐스캐디아 외부 1인플은 wrapper로 열 수 있지만, **핵심 목적은 공개 소스를 찾아 자체 온라인 다인플 검증에 활용하는 것**임을 잊지 않는다.
- [ ] 포크노바 1인플을 AI 대전으로 만들지 않는다.
- [ ] Supabase 이메일 Auth를 다시 쓰지 않는다.
- [ ] 비밀번호는 4자 이상 정책이다.
- [ ] 게임 취소는 현재 전원 동의다.
- [ ] 기존 Supabase 데이터가 날아가는 destructive SQL을 쓰지 않는다.
- [ ] service_role key를 프론트에 넣지 않는다.

# 20. 다음 대화 시작용 요약 프롬프트

다음 작업자가 이 README를 읽고 바로 이어갈 때는 아래 상태로 이해하면 됩니다.

> BoardMate Arcade v11.1은 GitHub Pages + Supabase 기반 모임용 보드게임 사이트다. 메인은 미니게임(펜토리니/Yahtzee), 1인플, 다인플, 마이페이지로 구성되어 있다. 리코셰는 삭제했고 다시 만들지 않는다. 자체 닉네임+4자 이상 비밀번호 로그인, 관리자 정지/퇴출, 자동 저장/재접속/접속 끊김, 진행 중 게임, 게임별 비공개 ELO와 메달, 대기실 방장 강퇴, 전원 동의 게임 취소가 구현되어 있다. 온라인 게임은 마스크맨/어콰이어/캘리코/캐스캐디아/포크노바 베타/더 게임/노터치 크라켄이다. 캘리코·캐스캐디아의 외부 1인플 GitHub Pages는 현재 wrapper로도 열지만, **다음 작업의 핵심은 그 공개 소스를 찾아 BoardMate 자체 온라인 캘리코/캐스캐디아의 보드 좌표·룰·점수 로직을 검증하는 것**이다. 캘리코 온라인은 육각 보드와 가장자리 22칸, 고양이 점 1/2/3 그룹 선택을 반영했다. 캐스캐디아 온라인은 새 사용자 제공 HTML로 교체되어 A/초심자·가족/중급 점수와 34% 회전 미리보기를 지원하며 BoardMate Supabase 자동 저장에 연결했다. 포크노바 온라인은 원본 자체의 미완성 요소가 있는 베타이며 1인플은 아직 만들지 않고, 나중에 아크노바 공식 솔로 룰 기반으로 만들 예정이다. 룰북 PDF는 ZIP에 넣지 않는다. 다음 작업 전 외부 Calico/Cascadia 저장소·라이선스 확인, Supabase 다기기 E2E, 캐스캐디아 재접속, 캘리코 실물 보드 정확성 검증이 우선이다.

# 21. v11 배포 전에 마지막으로 할 것

1. `config.js`에 실제 Supabase URL / anon key 확인
2. Supabase SQL Editor에서 **v11.1 `supabase.sql` 전체 Run** 또는 빠른 RPC 복구용 **`SUPABASE_RPC_FIX_v11_1.sql` 전체 Run**
3. 관리자 계정이 필요하면:

```sql
select public.admin_set_boardmate_admin('내닉네임', true);
```

4. GitHub에 폴더 내용 전체 덮어쓰기
5. 강력 새로고침
6. 다계정으로 방/재접속/취소/종료 테스트
