# v11.4.95 크립티드 ALPHA · 2026-11-05

## 이용 방법

다인플 → 새 방 만들기 → ALPHA의 크립티드 → 3~5명 입장 → 방장 게임 시작 → 기본/고급 모드 선택 순으로 진행합니다. 각자 비공개 단서를 확인한 뒤 단서에 맞지 않는 칸에 초기 큐브를 두 번 놓습니다. 이후 상대에게 질문하거나 자신의 단서에 맞는 칸을 탐색합니다.

`online-cryptid.html?demo=1`은 계정과 서버 저장을 사용하지 않는 로컬 연습입니다. 볼 플레이어를 바꾸면 다른 사람의 단서가 자동으로 가려집니다.

## 구현 범위

- 제공된 실물 지도 타일 6개의 지형·곰·쿠거 영역을 전사한 108칸 육각 지도.
- 기본 모드 구조물 6개, 고급 모드 구조물 8개와 부정 단서.
- 기본 4개·고급 4개 지도 배치에서 매 게임 단서를 새로 조합. 모든 단서를 합쳐 서식지가 정확히 하나이며 각 참가자의 단서가 추리에 기여하도록 검사.
- 초기 큐브 두 번 공유, 질문의 디스크/큐브 판정, 질문 거부 후 추가 큐브, 탐색의 시계 방향 응답, 기존 자기 디스크가 있는 탐색의 추가 디스크, 서식지 발견 시 종료.
- 단서에 맞지 않는 말 배치·상대 차례 행동·오래된 저장 요청 거부.
- 온라인에서는 서버가 응답을 판정하며 본인의 단서 문장만 전송. 방장에게도 상대 단서와 정답을 전달하지 않음.
- 재접속 조회, 3초 상태 확인, focus/online/pageshow 복귀 동기화. 지도 선택·갱신 시 내부 스크롤 유지.

ALPHA에서는 힌트 투표, 2인 변형과 ELO/전적 반영을 지원하지 않습니다. 추가 큐브·디스크를 놓을 유효 칸이 전혀 남지 않으면 진행이 멈추지 않도록 자동으로 계속합니다. 실제 책자의 문제 번호를 고르는 방식은 제공하지 않습니다.

## DB 적용과 호환성

Arena 프로젝트 `dtqhuorprcwehhoukbmu`에 `database/SUPABASE_CRYPTID_ALPHA_V11_4_95.sql`을 SQL Editor에서 적용했습니다. Note 프로젝트는 변경하지 않았습니다.

새 비공개 테이블 2개와 전용 API 4개를 추가합니다. 방의 게임 종류 제약은 기존 허용 항목을 보존하며 크립티드를 더합니다. 인원 제한 함수는 기존 22개 게임 결과를 유지하고 크립티드 3~5인을 추가합니다. 기존 테이블의 게임 상태·회원·진행방·평점을 초기화하거나 삭제하지 않습니다. 스크립트 재실행도 로컬 DB에서 검증했습니다.

운영 조회 결과: 지도 8개(기본 4/고급 4), 모두 108칸, RLS 테이블 2개, API 4개, anon/authenticated의 비공개 테이블 직접 읽기 불가, 기존 22개 게임 인원 제한 일치.

새 환경에서는 기존 BoardMate 스키마를 먼저 구성한 뒤 이 SQL을 추가 적용해야 합니다. 이전 통합 SQL에는 이번 크립티드 테이블이 포함되지 않습니다.
