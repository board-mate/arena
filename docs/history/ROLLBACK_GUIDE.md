# BoardMate Arena 롤백 가이드

## 원칙

업데이트 문서만으로는 실제 코드 롤백이 완전하지 않습니다. GitHub 저장소에서는 각 배포 시점을 커밋/태그로 남기고, 이 `docs/history`와 `database/history`를 함께 보존해야 합니다.

## 권장 릴리스 절차

1. 배포 전 현재 정상 버전을 커밋합니다.
2. 버전 태그를 생성합니다. 예: `v11.4.48`.
3. 변경 파일과 데이터베이스 SQL을 적용합니다.
4. E2E/스모크 테스트를 수행합니다.
5. 문제가 있으면 직전 태그/커밋으로 코드만 되돌립니다. DB 변경이 있었다면 `database/history`의 당시 스크립트와 변경 기록을 확인한 뒤 별도로 복구합니다.

## 주의

- 데이터베이스는 코드처럼 무조건 `git checkout`으로 되돌릴 수 없습니다. 데이터 손실 가능성이 있으므로 SQL 롤백은 변경 내용을 확인한 뒤 수동으로 해야 합니다.
- 과거 문서가 현재 코드보다 오래됐다는 이유만으로 삭제하지 않습니다. 회귀 원인 추적 자료로 보존합니다.
- 테스트 산출물/캐시/중복 이미지처럼 롤백 가치가 없는 파일만 CLEAN 대상입니다.
