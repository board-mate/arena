# v11.4.85 — Note 연동 해제와 메카배 스플렌더 대회

Arena 홈의 Note 공지·일정 조회 코드와 Note Supabase 설정을 제거했습니다. Note 앱과 그 데이터, Arena의 진행 중인 게임은 수정하지 않습니다. Instagram 피드는 유지합니다.

## 이용 경로

- 메뉴: **이벤트** → **메카배 스플렌더 대회**
- 목록: `index.html#/events`
- 대회: `index.html#/events/splendor-2026-10-30`
- 일정: 2026년 10월 30일 금요일 19:30 (한국 시간)
- 12~16명, A~D조 무작위 편성, 각 조 1위가 4인 결승 진출, 확장 미포함.
- 1등 스트라이크, 2등 컬러레또. 상품은 당일 사정에 따라 변경될 수 있습니다.

첨부 HTML의 대회 엔진과 12~16명 규칙을 추출했습니다. 원본 HTML 파일은 수정하지 않았습니다. 새 화면의 기록은 Arena DB에 저장되며, 방문자는 로그인 없이 대진표·순위·운영 안내를 확인할 수 있습니다. 15초마다 새 기록을 확인합니다. 서버 조회 실패 시 마지막 확인 기록임을 표시하며, 초기 조회 실패를 빈 대진으로 가장하지 않습니다.

## 관리자

상현, test, 관리자, 레한, 스테안의 **현재 회원 UUID**를 최초 마이그레이션 때 대회별 권한 테이블에 등록합니다. 닉네임이나 브라우저 저장값만으로 권한을 판정하지 않습니다. 기존 `boardmate_session_user`가 유효한 세션과 정지 여부를 확인하고, 모든 쓰기 RPC가 대회 권한을 재검사합니다.

이 권한은 대회 운영 전용입니다. 계정 정지·퇴출 등 사이트 전체 회원 관리 권한은 추가하지 않습니다. 다른 닉네임의 기존 전체 관리자도 자동으로 대회 운영 권한을 얻지 않습니다. 일반 대회 관리자가 탈퇴하면 권한도 삭제되며, 같은 닉네임으로 재가입해도 권한이 자동 승계되지 않습니다. 재실행도 권한을 새 계정에 자동 부여하지 않습니다.

**권한 관리:** 대회 화면 아래 **관리자 권한 관리**에서 기존 회원을 검색해 추가하거나 해지합니다. 추가된 관리자도 같은 권한 관리 기능을 사용합니다. 상현·관리자의 최초 회원 UUID는 최상위 관리자로 보호되어 누구도 해지·이전·강등할 수 없습니다. 보호된 계정의 탈퇴/삭제도 DB 외래키 연쇄 삭제를 통한 우회를 막기 위해 거부됩니다. 일반 관리자는 자신의 권한을 직접 해지할 수 없으며 다른 관리자에게 요청해야 합니다. 서버는 모든 변경 시 현재 권한을 재검사하고, 권한 변경 이력을 별도로 저장합니다. 권한 목록 버전 충돌도 검사합니다.

운영 순서:

1. 기존 Arena 로그인으로 로그인합니다. 대회에서 로그인 링크를 이용하면 대회로 돌아옵니다.
2. 참가 명단 12~16명을 입력하고 **무작위 추첨·공개**를 누릅니다.
3. 각 조의 모든 순위를 중복 없이 입력한 뒤 **순위 확정·저장**을 누릅니다.
4. 네 조가 확정되면 결승이 자동 생성됩니다. 결승 순위를 확정하면 최종 순위가 표시됩니다.
5. 예선 수정 시 결승 대진·결과를 초기화한다는 확인 후 수정합니다. 재추첨도 확인이 필요합니다.

각 저장은 revision 검사와 행 잠금으로 이전 기록을 덮어쓰는 충돌을 차단합니다. 충돌 시 최신 기록을 불러온 후 재입력합니다. 다른 항목의 미저장 입력은 개별 항목 저장 시 유지합니다. DB에 이전 상태가 보관되며, **결과 내려받기**의 JSON은 원본 HTML 매니저로 열 수 있습니다. 웹 UI에서 백업 가져오기는 제공하지 않습니다.

## 적용 순서

1. **Arena** Supabase 프로젝트 `dtqhuorprcwehhoukbmu`의 SQL Editor에서 `database/SUPABASE_EVENTS_V11_4_84.sql`을 실행합니다. Note 프로젝트에 실행하지 않습니다.
2. 마지막 조회 결과에 지정한 다섯 계정이 있는지 확인합니다. 회원이 누락되면 전체 트랜잭션이 중단되므로 실제 회원명을 확인해야 합니다. 새 계정을 만들어 대신 권한을 부여하지 않습니다.
3. 코드 변경을 `board-mate/arena`의 GitHub Pages 배포 브랜치에 반영합니다. HTML과 JS/CSS 모듈, 서비스워커를 함께 배포합니다.
4. 비로그인 대회 조회, 지정 관리자 로그인, 일반 회원의 조회 전용 화면을 확인합니다. 실대회 명단 없이 테스트 기록을 운영 서버에 저장하지 않습니다.

SQL 파일명은 최초 v84 명칭을 유지하지만 내용은 v85 누적 마이그레이션입니다. 최초 적용과 v84에서 갱신할 때 모두 같은 파일을 실행합니다. 재실행으로 해지한 일반 관리자가 복원되지 않습니다. SQL은 기존 세션/회원 테이블을 사용하는 추가 마이그레이션입니다. 회원, 게임, Note 테이블을 변경하거나 데이터를 지우지 않습니다. 네 개의 이벤트 테이블은 RLS를 켜고 직접 조회·쓰기를 차단하며, 공개 정보만 반환하는 조회 RPC와 권한이 있는 저장 RPC를 제공합니다. 운영자 UUID 및 수정 이력은 공개 조회 응답에 포함하지 않습니다.

## 검증

`pnpm install` 후 `pnpm test` 또는 `npm install` 후 `npm test`로 실행합니다. 테스트는 PGlite의 독립 PostgreSQL DB를 사용하며 운영 서버에 요청하지 않습니다. 기존 세션 함수는 공개 저장소의 기존 스키마를 확인한 뒤 테스트용 세션 함수로 대체하므로 **실제 운영 DB 스키마/권한 적용 확인은 별도**로 필요합니다.

- 자동 테스트 22개: 기존 알림·Calico 회귀, Note 호출 제거, 인원별 추첨과 진출, 익명/일반 회원 거부, 다섯 관리자 저장, 직접 테이블 접근 거부, 동시 수정 충돌, 잘못된 순위/대진 거부, 세션 만료/정지, SQL 재실행 및 닉네임 재사용 차단.
- 권한 테스트: 다섯 관리자 모두 권한 위임·해지, 위임받은 관리자도 권한 관리, 해지 후 기록 저장 거부, 최상위 관리자 해지·강등·계정 삭제 우회 차단, 닉네임 변경/재사용, 권한 버전 충돌과 감사 이력.
- 브라우저: 관리자 검색·추가·해지·보호 표시, 공개 조회, 관리자 추첨·예선 확정·결승 생성·최종 순위·예선 재수정, 안내 저장, 다른 항목 미저장 입력 보존, 일반 회원 입력창 미노출.
- 390px 모바일 화면: 메뉴 및 대회 페이지 확인, 가로 넘침 없음.
- 서버 적용 및 GitHub Pages 배포 여부는 실제 적용 후 별도로 확인해야 합니다.
